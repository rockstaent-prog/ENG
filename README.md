# こもれび — 英語のある毎日へ

日本語で使える、初心者向けの英語学習Webアプリです。React + Viteで動作します。

## 携帯に保存して使う（iPhone・Android）

携帯版はホーム画面に追加して使うアプリです。最初にEmmaの会話画面が開きます。

1. [こもれび携帯版](https://rockstaent-prog.github.io/ENG/)を携帯のSafariまたはChromeで開く。
2. 画面上の **「携帯に保存」** を押す。
3. iPhoneは **共有 → ホーム画面に追加 → 追加**、Androidは保存ボタン、または **︙ → ホーム画面に追加** を選ぶ。

初回の保存が終わると、アプリを閉じて通信を切っても、学習・練習会話・アバター表示を使えます。音声とマイクは端末・通信状態に依存します。更新版は次にアプリを閉じて開き直したときに反映され、会話や学習中に強制で再読み込みしません。

[携帯版のファイルをダウンロード（公開用ZIP）](https://github.com/rockstaent-prog/ENG/raw/refs/heads/main/preview/komorebi-mobile.zip)。これはHTTPSで公開するためのファイルです。ZIPを携帯で開くだけではインストールできません。GitHub Pagesの公開成功とURLはユーザーの画面で確認済みです。この環境から公開サイトへの接続は制限されています。App Store用IPAやAndroid APKではありません。

開発時は `npm run build:mobile` で `dist-mobile/` と配布ZIPを生成します。`npm run build:mobile:site` は公開用サイトだけを生成し、配布ZIPは変更しません。`npm run test:pwa` でホーム画面向け設定・保存・オフライン再起動を確認できます。

## すぐ操作してみる（PC向け）

[アプリのZIPをダウンロード](https://github.com/rockstaent-prog/ENG/raw/refs/heads/main/preview/komorebi.zip)して、ZIPの中の **「アプリを開く.html」** をダブルクリックしてください。パソコン向けです。インストールやAPIキーは不要です。詳しくは [開き方](preview/README.md) を参照してください。

開発中に1ファイル版を更新する場合は `npm run build:standalone`、操作確認は `npm run test:standalone` を実行します。通常の環境セットアップでは、配布済みファイルを再生成する必要はありません。

## できること

- 6レッスン・計30問：選択問題と単語の並べ替え。完了すると次のレッスンを解放。
- 間違えた問題の復習、24語・表現の単語帳、発音の読み上げ。
- XP、1日の目標、連続学習日数、週間グラフ、マイルストーン。
- カフェ・道案内・自己紹介の英会話。文字入力、返信例、日本語訳の表示切り替え。
- 対応ブラウザではマイクで英語を入力。認識した文を確認してから送信できます。
- 会話画面は大きなEmmaが中心。発話中は口・まばたき・頭の傾き・うなずき・肩の動きを連動。「履歴を広く」で文字を優先でき、読み上げの開始時には大きなアバターへ戻る。設定画面では姿を確認でき、選んだ画像の上下・左右・拡大率を保存。名前・画像・女性の英語音声の変更や、自動読み上げの設定も可能。
- PC・スマートフォンに対応。携帯では画面の高さ・縦横の向きに合わせて会話を表示し、キーボード表示中も入力欄を確保。学習記録はブラウザのlocalStorageに保存。

## 起動

Node.js 20.19以降（この環境では24.19）とnpmを使用します。

```sh
cd /workspace/ENG
npm ci
npm run dev -- --port 5173 --strictPort
```

起動後はポート5173で動作します。現在のクラウドオンボーディング画面では、実行中のアプリをチャット内で開く機能はありません。スマートフォンや別のブラウザで操作するには、下記の確認版を配信してURLを発行する必要があります。

```sh
npm run build       # dist/を生成
npm run preview -- --port 4173 --strictPort
npm test            # 学習記録・アバターの変形・保存案内・女性音声・通信などの37テスト
npm run test:e2e    # 実ブラウザの一連の操作。専用サーバーは自動起動・終了
npm run test:mobile # 携帯6サイズ・横画面・画面下の余白・キーボード表示の確認
npm run test:regressions # build後に実行。全30問・保存データ修復・通信失敗からの復帰
npm run build:mobile:site
npm run test:pwa    # 携帯版の保存・オフライン再起動・アバターの拡大と位置保存
```

ブラウザテストはシステムのChromiumを優先します。ない場合は `npx playwright install chromium` で用意してください。別のChromium実行ファイルは `BROWSER_EXECUTABLE` で指定できます。画像は `test-results/` に保存します。開発・プレビューのどちらでも `/api/chat` が動作します。通常の `npm run build` も、会話APIのない静的配信先ではブラウザ内のガイド会話に切り替わります。GitHub Pagesのようなサブパスでの配信には、相対パスで生成する次の確認版を使用してください。

## ブラウザで操作できる確認版

```sh
npm run build:preview
npm run test:preview
```

`dist-preview/` に、そのまま静的配信できる確認版を生成します。レッスン・単語帳・学習記録・Emmaの画像表示・アバター設定・ガイド会話はブラウザだけで動作し、サーバーやAPIキーは不要です。GitHub Pagesのような `/ENG/` 配下でも画像やCSSのパスが切れないことを実際のHTTP配信で検証しています。自由なAI会話は、APIサーバーを使う通常版で利用できます。

### GitHub Pagesで公開する場合

公開用のワークフロー `.github/workflows/pages.yml` を用意しています。`main` への反映時に自動で携帯版を公開する処理を実行します。手動実行も可能です。初期アバターの画像は公開ファイルに含まれます。リポジトリでPagesが無効の場合は、先にSourceをGitHub Actionsに設定する必要があります。

1. コードをGitHubリポジトリに反映する。
2. リポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選ぶ。
3. **Actions → Publish app preview → Run workflow** を実行する。
4. 成功した実行の **deploy / github-pages** に表示されるURLを開く。

既に別のホスティングを使っている場合は `dist-mobile/` の内容をHTTPSで配信できます。公開ワークフローはビルド、単体テスト、画面操作、携帯表示、全30問、不具合の再発確認、オフライン再起動を通過してから携帯版を配信します。ユーザーがリポジトリを公開に変更し、公開実行 #8 の build・deploy 成功と `https://rockstaent-prog.github.io/ENG/` が画面で確認されました。この環境ではGitHub APIとPagesへの接続がプロキシにHTTP 403で拒否されるため、公開サイトの操作は引き続き実機で確認が必要です。新しいコードの反映と、その版の公開完了は別に扱ってください。

## 会話モード

### ガイド会話（初期状態・キー不要）

場面ごとに入力の内容を判定して応答します。注文・温度・支払い、目的地と道案内、自己紹介・趣味などを練習できます。自由生成のAIではありません。想定外の話題には、練習できる話題と返信例を案内します。

### AIとの自由会話（任意）

サーバーに `ENGLISH_AI_KEY` があると、OpenAIの `gpt-4o-mini` を使って会話に応じた英語の返事・日本語訳・返信例・ひとことアドバイスを生成します。利用料は設定したAPIアカウントに発生します。

クラウド環境では、環境設定で個人用シークレット `ENGLISH_AI_KEY` を登録し、宛先 `api.openai.com` を許可してください。値をチャットに貼らないでください。設定が適用された後にサーバーを再起動します。ローカル開発では、必要に応じて `.env.example` を `.env.local` にコピーして設定します。キーはブラウザには配信しません。`VITE_` が付く変数にキーを設定しないでください。

AIモードはこの環境で認証情報が未設定のため、実サービスへの接続は未検証です。APIのリクエスト形式・応答の取り扱い・エラー処理は模擬応答でテスト済みです。通信失敗、不正な返事、30秒以内に返事が届かない場合は、入力を復元して再送できます。「練習会話で続ける」を押すと、その文をブラウザ内のガイド会話で再送し、その後も通信不要で練習できます。

## データと音声

「会話する」→「アバター設定」で会話相手を変更できます。PNG・JPEG・WebP（5MBまで）を選ぶと、縦横比を保って長辺768px以内に縮小し、このブラウザに保存します。画像を切り捨てず、プレビューを見ながら上下・左右の位置と拡大率を調整できます。画像データは会話APIには送りません。名前・音声・自動読み上げの設定もブラウザに保存されます。初期画像は提供画像をもとにアバター用に作成したもので、`public/avatars/conversation-partner.png` に同梱しています。読み込めない画像には用意したアバターを表示します。

会話画面の「あいさつを聞く」または各返事の「聞く」で再生できます。ZIP版は開くと会話画面が表示されます。自動読み上げは設定でオン・オフを切り替えられます。

Emmaは、提供画像をもとに作成した表情シート `public/avatars/emma-speaking.png` の口元と目元を重ね合わせ、口の開閉・丸める動き・まばたきを表現します。その顔全体を `src/avatar-motion.js` の軽量なメッシュで変形し、頭と肩を別の支点で動かして首元をなめらかにつなぎます。待機中の呼吸、発話中のうなずき・傾き・肩の揺れ、マイク入力中の首の傾きを加えています。ブラウザ内で最大約25fpsを目安に描画し、非表示中は描画を休みます。外部の有料アニメーションサービスは使いません。

音声の開始・終了に連動し、ブラウザが単語境界イベントを送る場合はそのタイミングに口やうなずきを合わせます。イベントを送らない音声では推定の読み上げ速度を使うため、口の動きと音が完全には一致しない場合があります。写真の頭・首・肩を動かす表現で、全身の3Dモデルではありません。ユーザーが追加した任意の画像には画像全体の動きを付け、Emma専用の口元は重ねません。

声はブラウザにある英語音声を使います。会話相手には女性と確認できる音声だけを使い、過去に保存された男性音声の指定は引き継ぎません。音声一覧の読み込みを最大1.5秒待ち、女性の声が見つからない場合は画面で案内します。男性の声や不明な既定音声への自動切り替えは行いません。Web Speech APIには共通の性別属性がないため、既知の音声名や提供元の女性ラベルを使って判定します。

画像の人物の声を再現する機能はありません。端末で「視差効果を減らす」などを設定している場合は頭・肩を固定し、まばたきも抑えます。自動テストでは音声イベントを模擬し、女性音声の選択、遅れて届く音声一覧、読み込み中の停止、口元・頭部・肩の画素変化、停止後の閉口、まばたき、発話開始時の大きな表示、自動読み上げを検証しています。実端末での音声出力はブラウザと利用可能な音声に依存します。

携帯向け表示は幅320〜430pxの縦画面と844×390pxの横画面をブラウザで確認しています。画面下の余白とキーボード表示時の高さ変化も模擬して確認していますが、実機のiPhone・Androidでの検証は未実施です。

携帯版のテストでは、公開先と同じ `/ENG/` 配下で実際のService Workerを登録し、manifest・アイコン・アプリ一式の保存を確認します。通信を切り、画面を閉じて新しく開き直し、保存した画像の位置・名前・Emmaの表情シート・会話・レッスンが使えることを検証しています。OSのインストール確認は模擬イベントで検証しており、実機のインストール完了や公開サイトでの動作を保証するものではありません。Safariの保存領域が削除された場合や、アプリのデータを消した場合は再び通信が必要です。

アカウントやクラウド同期はありません。学習記録はこのブラウザに保存され、ブラウザのサイトデータ削除で消えます。会話履歴は画面内のメモリに保持し、場面の切り替え・再読み込みでリセットされます。ガイド会話の内容は外部AIに送信しません。AIモードでは直近の会話がOpenAIに送信されます。

保存データの不正な数値や重複は読み込み時に除去し、復習問題は現在のレッスンから復元します。有効なXPや完了記録を保ちながら、古い・壊れた問題が画面を停止させるのを防ぎます。マイクを止めた後や場面変更後に届いた認識結果は入力に反映しません。

音声入力・読み上げはブラウザ機能に依存します。マイク入力にはHTTPSまたはローカル環境とマイクの許可が必要です。音声認識はブラウザの提供するサービスに送信される場合があります。文字入力はマイクなしで利用できます。

## 環境を再利用する場合

既存の `/workspace/ENG` チェックアウトを使用します。クラウドタスクは既に隔離されているため、ユーザーからの指示がない限りGit worktreeを追加しません。依存パッケージとファイルは保持できますが、サーバーのプロセスは新しいタスクで起動し直してください。
